# HistoryMinerva 项目概览

更新日期：2026-08-17

## 一句话定义

HistoryMinerva 是注册到 HistoryVulcan 的单一 CAD 模块。当前源码线为 `4.3.17`：纯前端（原 Mapping 中央停靠页，
Solid Edge → SolidWorks 受控转换，SolidWorks 装配体的特征整备（全部先转 XT 洗掉再识别），以及 SolidWorks 属性整备改名/洗图号）+ 纯后端（单一
`HistoryMinerva.Worker.exe`，内部路由映射转换、SWuse 建模与装配改名三类既有工作协议）。前身双模块（Mapping/SWuse）合同见
`b-Office/history/42-V4.1.0-HistoryMinerva模块合并计划.md` 与 `b-Office/history/swuse-v0.1/docs`。

## 当前范围

- 对外模块名为 `HistoryMinerva`、命令域为 `minerva`（唯一权威源 `HistoryMinervaIdentity`），源码版本 `4.3.17`；
  停靠页标题为短形 `Minerva`，窗口内部标识 `historyminerva`。
- 正式 Clio `z-Publish` 仍为 `4.3.16`，直到本工作区合并；源码 `4.3.17` 删除原零件特征树检测，已有 `SW/` 也一律重做：先转 XT 洗掉，再识别。
- UI 只配置转换来源和转换内容：`.par → .SLDPRT`、`.asm → .SLDASM`、`.SLDASM → .SLDASM`（SolidWorks
  特征整备）以及 `.SLDASM → 属性整备（改名）`。选中属性整备时填写图号前缀并按所选装配体层级就地改名，
  或按文件名第一个空格洗掉图号。
  两个顶栏等宽。SW 特征整备把源装配里的每个零件都先严格导出到 `XT/` 洗掉原特征树，
  再对 XT 跑特征识别与草图完全定义，再按源层级重建装配；不检测原零件是否已有特征。识别不可用时产物仍是压平后的导入体。设计与真机证据见
  `b-Office/history/45-V4.3.0-SW自整备转换管线.md`。
- `minerva.conversion.probe/run/strip/cancel` 只从 HistoryVulcan 前端执行，不投影到 MCP；
  `minerva.worker.show/hide/status/path/capabilities` 在后台权威表注册并作为只读 MCP 工具暴露。
- 页面探查、转换和取消只走命令总线；Worker 事件与最终结果进入 Vulcan 日志/控制台，不再回退为页面直调用。
- SWuse 独立窗口已删除（待打磨后回归）；其 C# 建模 API、Roslyn 编译与构建协议保留在后端。
- 内部程序集、Worker 路由、JSON 协议、XT/SW 默认输出和 COM 行为统一为 HistoryMinerva/SWuse 约束，
  不保留旧转换模块命名。SW 自整备链路已跑过真机门禁；Solid Edge 链路未改动，沿用既有真机证据。

## 宿主与数据

工程直接消费 `2026-023-HistoryVulcan/z-Publish` 3.11.1；`HistoryVulcan.Core.dll` 生产引用为
`Private=false`，模块包不得私带宿主 DLL。运行数据位于宿主数据根 `HistoryMinerva/`，Worker 请求和
探查结果分别位于 `HistoryMinerva/requests` 与 `HistoryMinerva/probes`。正式模块部署到 HistoryVulcan 前端与
服务端两个 `HistoryMinerva` 槽；部署时退役全部旧 `Mapping`、`SWuse` 与历史转换模块槽。
