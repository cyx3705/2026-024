# HistoryMinerva 4.3.14 技术合同

`history/` 保存版本化计划与迁移前事实。本文件是 HistoryMinerva 当前实现和验收的唯一技术真值。

## REQ-001 对外身份与兼容边界

- 模块名、部署槽和数据目录为 `HistoryMinerva`，命令域为 `minerva`，全部取自
  `HistoryMinerva.Contracts` 的 `HistoryMinervaIdentity` 唯一权威源；代码不得出现独立名称字面量。
- 停靠页标题为短形 `Minerva`，窗口内部标识 `historyminerva`；版本由
  `b-Code-HistoryMinerva/build/HistoryMinerva.Version.props` 唯一决定。
- 当前源码、源码清单为 `4.3.14`；正式 `z-HistoryMinerva` 在下次发布前仍为 `4.3.10`（DEC-011 的版本隔离规则继续有效）。
  行为不同时不得复用同一版本号，也不得用当前源码文档覆盖解释发布历史中的旧正式包。
- `minerva.conversion.probe/run/strip/cancel` 是前端命令，要求 UI 线程且 `AllowMcpExecution=false`；
  其中 probe 只读，run/cancel 为写命令，服务端前端代理负责跨进程转发，MCP 不出现这三条命令。
- `minerva.worker.show/hide/status/path/capabilities` 由后台模块上下文显式注册，全部只读并可投影 MCP；
  不再由 `MainClassType` 反射生成 `HistoryMinerva.*` 旧命令。
- 宿主命令表忽略大小写；`mapping.*`、`swuse.*` 旧指令域已作废，无兼容别名。
- 内部程序集与命名空间统一为 `HistoryMinerva.*`/`SWuse.*`；Worker JSON 请求/事件/结果协议、COM 调用和
  输出目录规则不变，且不保留旧转换模块命名兼容层。

## REQ-002 通用两栏 UI

- 页面根使用透明背景，宿主决定外层 Canvas；页面使用 `Shell.Brush.*`、`Shell.Font.*`、`Shell.Space.*`、
  `Shell.Radius.*`、`Shell.Size.*` 动态令牌，不在生产 XAML 固定颜色、字体或第二套控件模板。
- 顶部为两个等宽栏：转换来源、转换内容。转换内容为四项：`.par → .SLDPRT`、`.asm → .SLDASM`、
  `.SLDASM → .SLDASM`（SolidWorks 特征整备）、`.SLDASM → 属性整备（改名）`。选中项是界面到 Worker 之间**唯一**的源格式真值；
  选择装配体文件时按扩展名自动切到对应项，但若当前已是同格式的 SolidWorks 装配项（特征整备或属性整备），不得被文件选择切走。
  不另设格式开关。选中属性整备时底部改为图号前缀，隐藏特征/配合选项；主按钮为「按图号改名」，并并列「按空格洗图号」。
- 顶部每个等宽栏内，标签与来源/内容选择控件同处一行；正文和表头使用宿主正文层级，保持 13px 可读密度。
- 零件列表直接从表头开始，不保留独立的“零件”标题行；底部仅保留转换选项和主按钮，窄窗口允许按视觉顺序换行。
- Minerva 页是 `DockSide.Center` 单例中央业务页，页面不创建自己的窗口标题、停靠区或窗口按钮。
- 320px、浅色/深色和 100%/125%/150% DPI 下，来源选择、内容选择、选项和主操作保持可见可操作；长路径和映射名以省略号或换行处理。

## REQ-003 宿主上下文与数据

- UI 模块和命令类实现 `IModuleContextAware`，使用宿主 `CommandBus`、`IShellLog`、设置和数据根。
- `MappingRuntimePaths` 从 `IModuleContext.DataDirectory` 与 `module.dir` 推导模块数据目录、双槽路径、请求和探查目录。
- Worker 定位顺序为当前程序集目录、宿主进程基目录、`module.dir/HistoryMinerva` 部署槽，最后回退到宿主所在编号项目库（HistoryClio，或仍含 `HistoryVesta.git` 的旧根）下各项目的 `z-HistoryMinerva` 正式包；找不到时返回首候选供预检报告。
- 源 CAD 文件只读；扫描、探查和纯内存规划不创建 XT/SW 输出目录，环境检查通过后才创建。

## REQ-004 单一 Worker 与 CAD 生命周期

- 所有 COM 工作由单一 `HistoryMinerva.Worker.exe`（x64 STA）完成；入口按参数形态路由：
  HistoryMinerva 转换 `<verb> <json> --cancel <signal>`（4 参数），SWuse 构建 `--request <json>`（2 参数）。
- Solid Edge `SaveBody` 输出 Parasolid `.x_t`，SolidWorks 导入并保存 `.SLDPRT/.SLDASM`；装配层级、矩阵、特征守卫和配合回滚沿用既有 3.6.7 真机合同。SolidWorks 源见 REQ-005。
- SWuse 建模链（Roslyn dry-run 编译 + `SWuse.Api` + SolidWorks 零件构建）保留在协议层，无独立 UI。
- UI 不持有 CAD COM 对象；取消和卸载必须等待 Worker 收束，不终止宿主已有 CAD 会话。

## REQ-005 SolidWorks 自整备管线

- 源格式由 `ConversionSourceFormat` 承载，作为可选字段追加在四个请求记录**末尾**，缺省
  `SolidEdge`；没有该字段的历史请求 JSON 必须仍按 Solid Edge 执行。
- 分叉只发生在读装配与取零件两步：`SolidWorksAssemblyExplorer` 产出与 Solid Edge 探查
  **同形**的 `AssemblyProbeResult`，`SolidWorksPartPreparer` 负责零件整备。此后的拓扑排序、
  嵌套装配生成、组件变换校验、配合重建与复用判定两种源共用同一份实现。
- SolidWorks 源的**输出布局**不经 Parasolid 中转（`ConversionPathLayout.UsesParasolidHandoff`）：
  不产生交付用 `.x_t`、不创建 `XT/` 目录、不校验 `XtPath`。识别前的临时 `.x_t` 是零件整备内部步骤，
  不算输出布局。源目录里若有名为 `XT` 的文件，不得当成输出目录冲突。
- SolidWorks 组件 `GetPathName` 指向缺失文件时，若路径本身是 `.lnk` 或旁边有同名 `.lnk`，
  探查必须解析快捷方式目标；虚拟件仍记为未解析引用，并在诊断里标明。
- 装配探查的前置错误必须进入 `minerva.conversion.probe` 的**失败**结果文本（含错误类与原因）；
  不得把「解析完成，但有 N 个前置错误」报成成功。页面仍不绑定 `StatusText`，零件行「受阻」保留。
- SolidWorks 柔性子装配（或单独打开时姿态与总装不一致的子装配）按总装世界矩阵反算在位局部矩阵后生成；
  不得因气缸行程等柔性差异阻断转换。改写过的子装配不再重建其内部配合。同一子装配在总装中出现
  两种在位姿态时仍阻断。Solid Edge 仍按独立文档局部矩阵与世界矩阵互证，超差即阻断。
- 零件整备只在**副本**上进行：源零件复制到输出目录后以唯一临时名打开。开启特征识别时，哑实体和
  已有特征树的普通 SolidWorks 零件都先经 Parasolid 压平再交给 FeatureWorks；不得因源零件没有导入体
  而跳过识别。切到「特征整备」时界面默认勾选「识别特征与草图」。识别不可用、几何被改变或特征树
  语义错误时，产物退回源零件副本，必须与源逐字节相同。SolidWorks 永远不打开源零件。
- 产物绝不能是源文件本身：计划器与 Worker 校验器各自独立拦截一次。
- 源装配的固定组件译为 `SwFixedComponent` 关系，配合按 `IMate2` 类型译为 SW 重合/同心/距离；
  未实测的类型照实带类型号进报告，不猜。接地判定一律向 `MateTypeMapper` 询问 `MatePlanKind.Fix`，
  不得对单个接口名字面量比较。
- 配合几何取自被引用面的曲面参数乘组件变换，与目标装配侧收集候选走同一套换算；
  不消费 `IMateEntity2.EntityParams`。

## REQ-006 命令总线与无窗控制面

- 模块身份 `HistoryMinerva` 与命令域 `minerva` 分离；真实命令统一为 `minerva.<class>.<method>`，
  不注册 `HistoryMinerva.*`、`mapping.*` 或 `swuse.*` 兼容别名。
- 后台 Worker 命令必须通过 `IModuleContext.RegisterCommands` 进入 Vulcan 权威注册表；状态与路径使用
  `MappingRuntimePaths`/`WorkerLocator`，不得把 `AppContext.BaseDirectory` 当作模块目录。
- 页面选择来源后的探查、转换和取消都只执行 `CommandBus` 命令；总线失败不得回退到 ViewModel 直调用。
- Worker 中间事件通过 `CommandContext.Progress` 进入 `cmd:progress:minerva:conversion`，最终结果和错误
  通过命令总线与 `IShellLog` 进入 Vulcan 控制台。MCP 只暴露后台只读 Worker 查询，不远程执行 CAD。
- 页面不得使用 `MessageBox`，也不得绑定 `StatusText`/`WarningSummary` 显示全局提示；零件行状态仍作为转换事实保留。
- ViewModel 的异常与取消必须传播给命令处理器，不能把失败文本吞掉后返回成功结果；UI 模块不得重复直写最终结果日志。

## REQ-007 可执行质量门禁与 CI

- `Test-QualityGate.ps1` 是项目 `verify` 唯一入口，必须同时执行共享项目合同并阻断：非文档警告抑制、
  生产源码千行热点、项目/程序集/manifest/现行合同版本漂移、命令与模块 API 漂移、正式 z 文件边界或
  SHA 漂移，以及低于最低兼容版本的 HistoryVulcan 宿主或程序集身份漂移。
- `HistoryMinerva.sln` 是离线 CI 构建图，只包含四个生产工程、Smoke 与 UI Smoke；真实 CAD 探针不得进入
  云端必跑构建图，避免把没有 CAD 授权与桌面会话的托管机误报为产品回归。
- 推送和 PR 门禁必须锁定还原，Debug/Release 均以 warning-as-error 构建并运行 Smoke；Release 另跑
  320px 深色 150% DPI 与 1200px 浅色 UI Smoke、格式校验和候选包边界，任一步失败即阻断。
- 唯一 NuGet 依赖必须提交锁文件；CI 使用 `--locked-mode`，依赖图漂移必须显式更新锁文件后才能通过。
- 真机 `VERIFY-SW-SELF` 与 Solid Edge 门禁保持独立人工触发，不由无 CAD 环境的云端 CI 冒充执行。
- `b-Code-HistoryMinerva-Tests/tools` 只保留四个可重复执行的端到端门禁；一次性探索探针不得长期驻留，
  已确认结论必须进入生产代码、离线 Smoke、现行合同或历史证据后删除。

## REQ-008 SolidWorks 属性整备（本版仅改名）

- 本版只支持 SolidWorks 装配体改名，不改其它自定义属性，也不处理 Solid Edge。
- 图号前缀（如 `ZS-LHL`）由用户手写；代码不得把来源地区或机台功能写成固定规则。
- 文件名形态为 `图号 (空格) 原零件名称`；原名称保持不变，只在前面加图号。已带同一前缀图号的文件先剥掉旧图号再重编。
- 所选装配体的层级由其**当前文件名**推断：`前缀-00` 为总装，`前缀-NN-00` 为大组件，`前缀-NN-MM-00` 为小组件。尚无图号时按总装 `前缀-00` 处理。
- 总装的子装配编为大组件 `NN-00`，大组件的子装配编为小组件 `NN-MM-00`，小组件只允许零件层级 `NN-MM-KK`。小组件下的装配体、以及位于所选装配体目录之子文件夹中的文件，一律视为外购件/标准件：只给该装配体（或零件）一个零件图号，内部文件无图号。
- 改名在源文件所在目录就地执行，不换目录、不写 `XT/` 或 `SW/`。Worker 动词仍是 `--rename-assembly`；COM 必须先关闭相关文档，再 `File.Move` 并用 `ReplaceReferencedDocument` 更新父装配引用。未保存的已打开文档必须拒绝改名。
- 「按空格洗图号」是同一页的反向操作：按文件名**第一个空格**切开，去掉空格前的图号，只保留空格后的原名称。原名里若还有空格一律保留。没有空格的文件保持原名。遍历所选装配体全部文档，含标准件内部。不要求填写图号前缀。请求体在 `AssemblyRenameRequest` 末尾追加 `stripBySpace`，缺省 false。
- 探查、按图号改名、按空格洗图号、取消走 `minerva.conversion.probe/run/strip/cancel`，不新增 MCP 命令。

## 依赖与发布

- .NET 8、Windows Desktop Runtime、Solid Edge 2020 COM、SolidWorks 2025 SP5 COM、FeatureWorks。
- HistoryVulcan 最低兼容版本为 3.11.1，消费快照路径为 `../2026-023-HistoryVulcan/z-HistoryVulcan`；
  模块生产引用保持 `Private=false`，宿主重建不因字节级 SHA 变化而触发模块源码变更。
- `z-HistoryMinerva` 是唯一正式消费目录（清单与运行产物同处）；候选只由 `Build-HistoryMinervaPackage.ps1`
  从 Release 输出生成，正式提升和文档镜像由 Diana 集中事务控制，备份必须位于 Modules 目录之外。
