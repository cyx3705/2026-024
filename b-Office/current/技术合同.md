# HistoryMinerva 4.8.1 技术合同

`history/` 保存版本化计划与迁移前事实。本文件是 HistoryMinerva 当前实现和验收的唯一技术真值。

## REQ-001 对外身份与兼容边界

- 模块名、部署槽和数据目录为 `HistoryMinerva`，命令域为 `minerva`，全部取自
  `HistoryMinerva.Contracts` 的 `HistoryMinervaIdentity` 唯一权威源；代码不得出现独立名称字面量。
- 停靠页标题为短形 `Minerva`，窗口内部标识 `historyminerva`；版本由
  `b-Code-HistoryMinerva/build/HistoryMinerva.Version.props` 唯一决定。
- 当前源码、源码清单与正式 `z-Publish` 候选线为 `4.8.1`（DEC-011 的版本隔离规则继续有效）。

- Aurora 页面只允许声明式组件：来源选择使用 `sourcePicker`，布尔转换选项使用 `switch`，不得恢复自注册页面、状态摘要表或“设置来源/应用内容”按钮。
  行为不同时不得复用同一版本号，也不得用当前源码文档覆盖解释发布历史中的旧正式包。
- `minerva.conversion.probe/run/strip/cancel` 是前端命令，要求 UI 线程且 `AllowMcpExecution=false`；
  必须在 `Attach` 登记进宿主总线（CreateUi 注入 ShellUi 之前 FinalizeMetas 已封表），MCP 不出现这四条命令。
- `minerva.worker.show/hide/status/path/capabilities` 由后台模块上下文显式注册，全部只读并可投影 MCP；
  不再由 `MainClassType` 反射生成 `HistoryMinerva.*` 旧命令。
- 宿主命令表忽略大小写；`mapping.*`、`swuse.*` 旧指令域已作废，无兼容别名。
- 内部程序集与命名空间统一为 `HistoryMinerva.*`；Worker JSON 请求/事件/结果协议、COM 调用和
  输出目录规则不变，且不保留旧转换模块或 SWuse 建模命名兼容层。

## REQ-002 通用两栏 UI

- 页面根使用透明背景，前端决定外层 Canvas；页面使用 `Aurora.Brush.*`、`Aurora.Font.*`、`Aurora.Space.*`、
  `Aurora.Radius.*`、`Aurora.Size.*` 动态令牌，不在生产 XAML 固定颜色、字体或第二套控件模板。
- 顶部为两个等宽栏：转换来源、转换内容。转换内容为四项：`.par → .SLDPRT`、`.asm → .SLDASM`、
  `.SLDASM → .SLDASM`（SolidWorks 特征整备）、`.SLDASM → 属性整备（改名）`。选中项是界面到 Worker 之间**唯一**的源格式真值；
  来源输入只跟当前转换内容走，不得按文件扩展名改转换内容，也不得把装配体和零件文件夹混在同一个选择器里。
  装配体三项只选择对应的单个装配体文件（`.asm` 或 `.SLDASM`）；零件项只选择文件夹。
  `minerva.ui.picksource` 与 `minerva.ui.source` 必须带上页面当前转换内容。属性整备、特征整备和 Solid Edge 装配转换都只选择对应装配体文件；零件项只选择文件夹。
  选择来源只写入路径，不解析装配体；解析只由「解析装配体」按钮触发。
  `minerva.ui.source` 在文件对话框关闭后不得返回失败：类型不对或路径无效时说明原因并保持原到来源，命令仍成功。失败指令会让宿主抢控制台并重排停靠，整窗卡死。
  设置来源只核对当前转换内容要求的输入形态，不得在 UI 线程探测文件是否存在。
  空图号前缀不得作为失败指令去抢控制台。
  解析装配体、写入、按空格洗图号必须按页面当前转换内容执行；写入只就地改文件名并写零件属性，不得生成 `XT/` 或走特征整备。
  特征整备与属性整备的解析装配体都只收录与所选装配体同级目录的文件；子文件夹中的外购件不打开、不进零件表。
  不另设格式开关。选中属性整备时去掉识别特征、失败继续、重建装配关系；底部第一行是图号前缀与「设计」，第二行是材料 / 表面处理 / 热处理三个一键批量框。
  顶部动作为「解析装配体」「一键设置日期」「写入」「按空格洗图号」「取消」。零件表为文件、状态、材料 / 表面处理 / 热处理三个可点列，不再使用「改名后预览」或特征/草图列；规划后的文件名直接显示在「文件」列。
  解析完成后洗图号按钮保持可点；没有可洗文件或未填前缀时，命令返回可读原因，不得沿用转换状态文案。
- 顶部每个等宽栏内，标签与来源/内容选择控件同处一行；正文和表头使用宿主正文层级，保持 13px 可读密度。
- 零件列表直接从表头开始，不保留独立的“零件”标题行；底部左侧是「打开」装配结构，右侧是转换选项和主按钮，窄窗口允许按视觉顺序换行。
- 装配结构不再占用左侧固定栏或正文顶部展开条。四种转换的默认正文都只铺零件表。
  装配转换下点击左下角「打开」后，装配结构从正文左侧弹出；再点「收起」关闭。零件文件夹模式隐藏该按钮。
- Minerva 页是 `DockSide.Center` 单例中央业务页，页面不创建自己的窗口标题、停靠区或窗口按钮。
- 320px、浅色/深色和 100%/125%/150% DPI 下，来源选择、内容选择、选项和主操作保持可见可操作；长路径和映射名以省略号或换行处理。

## REQ-003 宿主上下文与数据

- UI 模块和命令类实现 `IModuleContextAware`，使用宿主 `CommandBus`。页面只通过
  `minerva.ui.describe` 返回 Aurora 描述式 JSON，由 Aurora 统一创建组件和停靠页；
  模块不得注册 `minerva.ui.pane`、不得返回 WPF `UIElement`。
- 页面取数统一走 `minerva.ui.data view=parts|content`，外部副作用统一由
  `minerva.ui.actions` 声明动作 ID，再映射到 `minerva.conversion.*` 或 `minerva.ui.*` 命令。
- `MappingRuntimePaths` 从 `%AppData%\HistoryVulcan` 推导模块数据目录、部署槽、请求和探查目录。
- Worker 定位顺序为当前程序集目录、宿主进程基目录、`module.dir/HistoryMinerva` 部署槽，最后回退到宿主所在编号项目库（HistoryClio，或仍含 `HistoryVesta.git` 的旧根）下各项目的 `z-Publish` 正式包；找不到时返回首候选供预检报告。
- 源 CAD 文件只读；扫描、探查和纯内存规划不创建 XT/SW 输出目录，环境检查通过后才创建。

## REQ-004 单一 Worker 与 CAD 生命周期

- 所有 COM 工作由单一 `HistoryMinerva.Worker.exe`（x64 STA）完成；只接受转换协议
  `<verb> <json> --cancel <signal>`。历史 SWuse 双参数 `--request <json>` 建模链已删除。
- Solid Edge `SaveBody` 输出 Parasolid `.x_t`，SolidWorks 导入并保存 `.SLDPRT/.SLDASM`；装配层级、矩阵、特征守卫和配合回滚沿用既有 3.6.7 真机合同。SolidWorks 源见 REQ-005。
- UI 不持有 CAD COM 对象；取消和卸载必须等待 Worker 收束，不终止宿主已有 CAD 会话。

## REQ-005 SolidWorks 自整备管线

- 源格式由 `ConversionSourceFormat` 承载，作为可选字段追加在四个请求记录**末尾**，缺省
  `SolidEdge`；没有该字段的历史请求 JSON 必须仍按 Solid Edge 执行。
- 分叉发生在读装配与导出 XT：`SolidWorksAssemblyExplorer` 产出与 Solid Edge 探查
  **同形**的 `AssemblyProbeResult`，但 SolidWorks 探查不打开子文件夹中的外购件，只收录与所选装配体同级的文件。
  `SolidWorksXtExporter` 把源零件副本严格导出为交付用 `.x_t`。
  此后的导入识别、拓扑排序、嵌套装配生成、组件变换校验、配合重建与复用判定两种源共用同一份实现。
- SolidWorks 源的**输出布局**经 Parasolid 中转（`ConversionPathLayout.UsesParasolidHandoff`）：
  产生交付用 `.x_t`、创建 `XT/` 目录、校验 `XtPath`。转换必须分成两步：先导出 XT（进度「导出 XT」），
  再对已落地的 XT 做 FeatureWorks 识别（或哑实体导入）。源目录里若有名为 `XT` 的文件，视为输出目录冲突。
- SolidWorks 组件 `GetPathName` 指向缺失文件时，若路径本身是 `.lnk` 或旁边有同名 `.lnk`，
  探查必须解析快捷方式目标；虚拟件仍记为未解析引用，并在诊断里标明。
- 装配探查的前置错误必须进入 `minerva.conversion.probe` 的**失败**结果文本（含错误类与原因）；
  不得把「解析完成，但有 N 个前置错误」报成成功。页面仍不绑定 `StatusText`，零件行「受阻」保留。
- SolidWorks 柔性子装配（或单独打开时姿态与总装不一致的子装配）按总装世界矩阵反算在位局部矩阵后生成；
  不得因气缸行程等柔性差异阻断转换。改写过的子装配不再重建其内部配合。同一子装配在总装中出现
  两种在位姿态时仍阻断。Solid Edge 仍按独立文档局部矩阵与世界矩阵互证，超差即阻断。
- 零件转换只在**副本**上进行：导出打开的是唯一临时名副本，不得打开源零件。特征整备不检测
  原零件有没有特征树；已有 `SW/` 产物也一律重做。识别关闭时仍先导出 XT 再哑实体导入；
  识别失败、未激活、语义不合规或几何被改坏时产物仍是压平后的导入体，不得把源特征树拷回去。
  切到「特征整备」时界面默认勾选「识别特征与草图」。VERIFY-SMOKE 禁止生产代码写出「跳过整备」或「源零件已有特征树」；VERIFY-SW-SELF 要求每个零件都留下交付用 XT。
  从已打开零件另存 `.x_t` 必须 Silent|Copy，并把 Parasolid 版本钉成 latest；已有坏 XT 重导，不把格式错误当成整批失败。
- 产物绝不能是源文件本身：计划器与 Worker 校验器各自独立拦截一次。
- 源装配的固定组件译为 `SwFixedComponent` 关系，配合按 `IMate2` 类型译为 SW 重合/同心/距离；
  未实测的类型照实带类型号进报告，不猜。接地判定一律向 `MateTypeMapper` 询问 `MatePlanKind.Fix`，
  不得对单个接口名字面量比较。
- 配合几何取自被引用面的曲面参数乘组件变换，与目标装配侧收集候选走同一套换算；
  不消费 `IMateEntity2.EntityParams`。

## REQ-006 命令总线与无窗控制面

- 模块身份 `HistoryMinerva` 与命令域 `minerva` 分离；真实命令统一为 `minerva.<class>.<method>`，
  不注册 `HistoryMinerva.*`、`mapping.*` 或 `swuse.*` 兼容别名。
- 后台 Worker 命令必须通过 `IModuleContext.RegisterCommands` 进入 Vulcan 权威注册表；状态与路径使用
  `MappingRuntimePaths`/`WorkerLocator`，不得把 `AppContext.BaseDirectory` 当作模块目录。
- 页面选择来源后的探查、转换和取消都只执行 `CommandBus` 命令；总线失败不得回退到 ViewModel 直调用。
- Worker 中间事件通过 `CommandContext.Progress` 进入 `cmd:progress:minerva:conversion`，最终结果和错误
  通过命令总线与 `IShellLog` 进入 Vulcan 控制台。MCP 只暴露后台只读 Worker 查询，不远程执行 CAD。
- 页面不得使用 `MessageBox`，也不得绑定 `StatusText`/`WarningSummary` 显示全局提示；零件行状态仍作为转换事实保留。
- ViewModel 的异常与取消必须传播给命令处理器，不能把失败文本吞掉后返回成功结果；UI 模块不得重复直写最终结果日志。

## REQ-008 SolidWorks 属性整备（改名 + 写零件属性）

- 本版支持 SolidWorks 装配体改名，并在同一次操作里写零件「自定义」属性；不处理 Solid Edge。
- 图号前缀（如 `ZS-LHL`）由用户手写；代码不得把来源地区或机台功能写成固定规则。
- 文件名形态为 `图号 (空格) 原零件名称`；原名称保持不变，只在前面加图号。已带同一前缀图号的文件先剥掉旧图号再重编。
- 所选装配体的层级由其**当前文件名**推断：`前缀-00` 为总装，`前缀-NN-00` 为大组件，`前缀-NN-MM-00` 为小组件。尚无图号时按总装 `前缀-00` 处理。
- 总装的子装配编为大组件 `NN-00`，大组件的子装配编为小组件 `NN-MM-00`，小组件只允许零件层级 `NN-MM-KK`。小组件下的装配体视为零件，内部文件无图号。子文件夹中的外购件/标准件解析时直接跳过：不打开、不编号、不洗名、不特征整备。
- 改名在源文件所在目录就地执行，不换目录、不写 `XT/` 或 `SW/`。Worker 动词仍是 `--rename-assembly`；COM 必须先关闭相关文档，再 `File.Move` 并用 `ReplaceReferencedDocument` 更新父装配引用。未保存的已打开文档必须拒绝改名。
- 主按钮是「写入」：改名与写属性是同一次操作，先改名并更新父装配引用，全部收工后再逐个打开零件写属性并保存。顺序不得颠倒——`ReplaceReferencedDocument` 要求相关文档处于关闭状态。请求体在 `AssemblyRenameRequest` 末尾追加 `writeProperties`，缺省 false；`RenameEntry` 末尾追加可选 `properties`，缺省 `null`，没有这两个字段的历史请求 JSON 仍是一次纯改名。
- 属性**只写识别出的零件**：拿到图号的 `.SLDPRT`。装配体、小组件内部未编号件和子文件夹外购件一律不写。判据 `AssemblyRenamePlan.IsWritablePart` 由界面与 Worker 各判一次。
- 八个属性槽的名字与两个固定值集中在 `PartPropertyNames`，代码其它位置不得出现字面量：图号、**名称**、**类型选择**、日期、设计、材料、表面处理、热处理；「类型选择」恒为 `机加件`，「日期」为文本型 `yyyy/MM/dd`。
- 槽名的**唯一权威来源是属性标签模板文件**，不是界面上看到的标题：`2026-025-实验室测绘/z-SW模板配置/03 属性模板/精密零件属性.prtprp`。该文件是 XML，每个 `<Control>` 的 `Label`（界面标题）与 `PropName`（真实属性名）是两个字段，可以不同——「类型选择」即是。禁止从截图或界面标题推断槽名。
- **属性写「配置特定」，不写文档级。** 该模板 17 个控件全部 `ApplyTo="Config"`，因此 `CustomPropertyManager` 必须传**活动配置名**。传空串写成文档级不会报任何错，只是用户打开属性标签页看到的还是空的。
- 写入用 `CustomPropertyManager.Add3` 加 `swCustomPropertyDeleteAndAdd`；不得用 `OnlyIfNew`——槽已存在时它一个字都不写。写完必须用 `Get6` 读回比对：`Add3` 返回 0 只代表调用被接受，链接到方程或只读的槽会静默不动。`Get6` 的第六个 out 参数是 **bool**（LinkToProperty），传 int 会让反射按 `Boolean&` 绑定失败，表现为"整备全部失败但看不到原因"。
- 写之前用 `GetNames` 对一次已有槽名：`Add3` 遇到不存在的名字会**新建**槽而不是报错，模板槽仍旧是空的。新建了槽必须在事件里点名说出来。
- **三个属性槽都不是自由文本，界面只让选不让填。** 「表面处理」「热处理」在模板里是 `ComboBox`，候选写在 `<Data SourceType="List">` 里；「材料」接的是 SolidWorks 材质库。往它们写模板候选之外的字符串，属性标签上看不出任何变化，明细表与图框也对不上——这是一种静默失败。
- **「材料」要写两处，缺一不成。** 模板里它是 `Mode="SWProperty"`、默认值 `SW-Material`，是一条指向零件材质的链接，不是文本。写材料的正确做法是：先 `IPartDoc.SetMaterialPropertyName2(活动配置, 材料库, 材质名)` 把材质应用到零件，再把「材料」槽写回 `SW-Material` 让链接成立。只写文本改不动那一栏，还会把链接换成静态文本。材质名脱离材料库应用不上去（传空库名不报错也不生效），因此 `PartPropertyWrite` 末尾追加 `MaterialDatabase`，缺省空串；只有名字没有库时 Worker 必须当场报错停批，不得放过去。
- **候选运行时读机器上的真实来源，不写死在代码里，也不写死本机路径。** 「材料」候选取当前用户在 SolidWorks 里**收藏**的材质（`HKCU\Software\SolidWorks\SOLIDWORKS <年份>\Material` 下的 `_FavMaterialN`，条数以 `__NumOfFavs` 为准——超出的是取消收藏后的残留）；「表面处理」「热处理」候选取属性标签模板目录（同分支 `ExtReferences\Custom Property Folders`）下所有 `.prtprp` 里对应 `PropName` 的 `<Item>`。选版本键时只认后缀为四位年份的，`SOLIDWORKS CAM` 是同前缀的兄弟键，按名字倒序会取到它。读不到时退回 `PartPropertyNames` 里抄自模板的兜底候选，页面照常能开；材料没有兜底，凭空编一个材质名比不给更糟。
- 三个下拉的首项恒为 `PartPropertyNames.NoWriteOption`（「（不写）」），落到模型层折成空串。Aurora 的选项框只能在候选之间轮换，没有「清空」这个动作，少了这一项用户点错一次就退不回不写了。
- 空串表示「这一槽本轮不写」，Worker 跳过它，不得把模板里已有的值抹成空。
- 「图号」属性的值与文件名里的图号完全一致，由同一个 `DrawingNumber.Text` 给出，不另算一遍。
- 「设计」与「日期」各由一个入口一次刷满全部零件：`minerva.ui.property field=designer|date`。日期取系统当日。
- 「材料」「表面处理」「热处理」是零件表里三个可点列，点单元格经 `minerva.ui.cell` 弹 `aurora.ui.dialog kind=choice` 逐行选；顶部另有三个一键批量下拉（`textbox` + `mode=select`）走 `minerva.ui.property field=material|surface|heat`，候选由 `optionsSource` 取 `minerva.ui.data view=materials|surfaces|heats`（不写进页面描述，否则改一次模板或收藏就要重启宿主才生效）。改完必须 `aurora.ui.refreshdata node=sw-property-parts`，否则界面停在旧值上。Aurora 的 `cellAction` 不触发空单元格，因此会写属性的零件行在空值时必须渲染占位符，不写属性的行留真空保持不可点。
- 用户填的三个槽按**源文件全路径**记账，改图号前缀导致计划与零件行整份重建时必须搬回来；换来源装配时清空。
- 「写入」的可执行判据是 `AssemblyRenamePlan.CanWrite` 而不是 `CanRename`：文件名已与规则一致但属性还没写时，写入按钮必须可点。整份 `Entries` 都要送到 Worker，只送待改名条目会让第二次写入一个属性都写不进去。
- 「按空格洗图号」是同一页的反向操作：按文件名**第一个空格**切开，去掉空格前的图号，只保留空格后的原名称。原名里若还有空格一律保留。没有空格的文件保持原名。只遍历所选装配体同级目录文档，不含子文件夹外购件。不要求填写图号前缀。请求体在 `AssemblyRenameRequest` 末尾追加 `stripBySpace`，缺省 false。洗图号同时把零件的「图号」属性清成空串（保留槽，不删槽），其余六槽不动。
- **「名称」没有界面入口**（4.8.1）。它的值是文件名里图号之后的那一段原零件名称，随改名一起写；让用户在旁边再填一遍只会制造「文件名叫阀体、属性里写着阀盖」的两份真话。计划器把它算在 `RenameEntry.PartName`（末尾追加，缺省空串），载荷在 `PartPropertyWrite.Name`（同样末尾追加）。洗图号不动这一槽——那条路只清「图号」。
- **三个槽的现值在解析装配体时就读回来**（4.8.1），作为零件表的预填值：`AssemblyProbeResult.PartProperties` 末尾追加，缺省 `null`，逐个唯一 `.SLDPRT` 一条。读数走装配里**已经载入的组件文档**，不为此另开零件——几百件的装配那样要重开几百次；材料读 `GetMaterialPropertyName2` 的名字**与材料库**，只有名字的材质应用不回零件。任何一格读不到就留空串，不把探查拖成失败。表格一片空白时用户唯一能做的是把已有的值再选一遍，选错一格就把零件上原本正确的材质换掉了，而属性标签上看不出任何异样。用户改过的那一格盖过读回的现值。
- **三个下拉的候选也在解析那一拍认一次**（4.8.1，`SolidWorksPropertyOptions.Refresh`），之后整轮整备复用同一份。原先每点开一格、每展开一次下拉都要重读注册表并解析模板目录下全部 `.prtprp`，几百行的表就是几百次同样的磁盘往返，而且全落在 UI 线程上。用户改了模板或收藏，重新解析一次装配体即生效，仍不需要重启宿主。
- **写入或洗图号收工后索引自动跟到新文件名上**（4.8.1），不需要重新选来源、重新解析。按磁盘实况（目标存在且源已消失）算出真的改成了的那一批，据此重写探查结果、三个槽的记账、来源装配路径、装配树与改名计划，并**重新计算源装配 SHA256**——`ReplaceReferencedDocument` 会重写父装配，不更新哈希的话第二次写入会被「源装配体在解析后发生变化」直接挡住，属性一个也写不进去。部分失败时只挪真的改成了的那几个。源装配此刻读不到（被占用或改名失败留下半截）时才要求重新解析。
- **零件表不再有「改名后预览」列**（4.8.1）：改完之后的文件名直接显示在「文件」列。同一个东西占两列本就多余，而改名成功之后「文件」那一列显示的还是一个已经不存在的文件。
- 改名条目 id 由**源文件全路径**定死，不是 `Guid.NewGuid`（4.8.1）。改一次图号前缀整份计划都要重建，随机 id 会让每一行都换身份：界面只能整表清空重填（几百个零件就是几百次控件重建，也就是"改一格卡一下"），而且用户此刻点开的那一格会指向一个已经不存在的 id。零件行据此**原地更新**；确需整表替换时只发一条 Reset，不逐行发 2N 条集合变更通知。按行 Id 找行走索引，不用 `FirstOrDefault` 线性扫。
- 探查、写入、按空格洗图号、取消走 `minerva.conversion.probe/run/strip/cancel`；`minerva.ui.property` 与 `minerva.ui.cell` 是本机界面命令，`HiddenReason` 非空，不新增 MCP 命令。
- 写入或洗图号失败时，命令的最终消息必须带上 Worker 报回的**第一条失败原因**，不得只说「详见 Vulcan 控制台」——进度事件混在几十条里，用户看到的就是一个没有原因的红叉。
