## DEC-013 SolidWorks 源走"就地整备"，不复用 Solid Edge 的中转往返

- 状态：已接受
- 日期：2026-08-11
- 决策：源格式由 `ConversionSourceFormat` 承载（缺省 `SolidEdge`，作为可选字段追加在四个请求记录
  末尾），分叉只发生在读装配与取零件两步；SolidWorks 源不经 Parasolid 中转，零件在**副本**上
  就地识别，识别不可用时产物退回与源逐字节相同的零件副本。此后的拓扑排序、嵌套装配生成、
  变换校验、配合重建与复用判定，两种源共用同一份实现。
- 原因：源已经是 `.SLDPRT`，再绕一圈 XT 只会引入中转误差和一整套本可以不存在的失败模式；
  而"同形读数 + 共用下游"让新源格式不必复制任何既有逻辑，也就不会分叉出第二套行为。
- 后果：SW 源不产生 `.x_t`、不创建 `XT/` 目录、不校验 `XtPath`；降级产物字节等于源文件，
  比"重新导入哑实体"更干净。历史请求 JSON 没有该字段，必须仍按 Solid Edge 执行——
  这个缺省值是全部向后兼容性的唯一依据。产物绝不能是源文件本身，计划器与 Worker 校验器各拦一次。
- 细节与真机证据见 `b-Office/history/45-V4.3.0-SW自整备转换管线.md`。

## DEC-020 旧平铺产物只属于 Solid Edge 源；"已存在"必须跟随识别开关

- 状态：已接受
- 日期：2026-08-12
- 决策：V3.0 时代的旧平铺产物（源目录里同基名的 `XT`/`SLDPRT`）只对 Solid Edge 源成立，由
  `ConversionPathLayout.HasLegacyFlatLayout` 唯一判定；SolidWorks 源不得回退到该路径。装配模式下
  开启特征识别时，已有产物一律重做，零件行状态显示"待整备"而非"已存在"。
  `PreflightValidator` 与 `WorkerRequestValidator` 保持同一口径：扩展名按源格式取，无 Parasolid
  中转时不校验 XT，只在源格式为 Solid Edge 时要求 Solid Edge COM。
- 原因：SolidWorks 源的"旧平铺产物路径"按构造就是源零件本身。回退分支把每个零件判成"已存在"，
  并把产物路径改写回源文件，计划阶段随即以"产物会覆盖源零件本身"整轮阻断——SW 自整备在默认输出
  目录下完全不可用。上一版用例传了自定义输出目录，正好关掉回退分支，因此没有暴露；而界面两个
  自定义目录传的都是 `null`。同时 `PreflightValidator` 未随 V4.3 更新，仍写死 `.par`/`.asm`。
- 后果：SW 自整备在默认 `SW/` 输出目录下可用；Solid Edge 的旧平铺复用行为不变。涉及产物存在性
  或源格式的用例必须覆盖 `customSolidWorksDirectory` 为 `null` 的参数组合，即界面真正产生的那一组。
  源码版本升为 4.3.3，正式 `z-Publish` 同步提升；本轮只跑过离线门禁，真机 CAD 门禁未执行。

## DEC-021 特征识别的三条真机口径

- 状态：已接受（第 1 条被 DEC-029 取代）
- 日期：2026-08-12
- 决策：
  1. **源零件没有导入体 = 无需整备**，在识别之前直接原样交付，且**不计入**"连续未识别"计数。
  2. **残留导入体属于部分识别**，只要建成了造型特征就保留整棵特征树，如实报"建成 N 个、另有 M 处未识别"；
     只有"报成功却零造型特征""几何被改坏""钣金误识别"才丢弃。
  3. **专属会话产不出特征**。会话故障后重试会起新 SolidWorks 进程，而 FeatureWorks 的自动识别要求该
     进程内先由人工识别过一次，新进程按定义未激活。该路径只保证几何落盘，重试时主动关闭识别并如实说明。
- 原因（2026-08-12 真机实测，12位消解器样件，SolidWorks 2025 SP5）：
  - `SetAdvancedOptions` 返回 false 有**两种**成因——会话未激活、活动文档里没有可识别的导入体。
    旧代码把两者都当成"未激活"。实测批次头两个零件恰好已整备好，连续两次"未识别"即触发整批降级，
    真正待整备的 BJ10B-04/05 一次都没被识别，12 个零件全部交付哑实体。
  - BJ10B-04 在已激活会话里识别 30 项并全部建成（16 旋转、6 孔向导、5 圆角），仅因残留一个
    `Imported1` 就被旧语义守卫整棵丢弃。守卫在扔掉好结果。
  - 同一零件同一参数：未激活会话识别 0 个，人工点过一次之后识别 30 个。激活状态是进程内状态，
    不跨进程、退出不保留。
- 后果：特征整备无法真正无人值守——每次 SolidWorks 重启后需人工先做一次识别。此约束应在界面和
  文档中明示，不能让用户跑完整批才发现全是哑实体。批次收尾必须重述该结论。
- 验收口径：用户依据早期实测，约 30% 的零件本就无法识别出特征；当前质量已达预期，本轮不再追加修复。
- 保留事项（非缺陷，供后续决策）：几何守卫阈值 `MaximumFeatureWorksVolumeRelativeDeviation = 2e-5`
  标定自 Solid Edge 的 XT 导入件，从未针对 SW 自整备验证。实测 BJ10B-04 偏差 4.77e-4、
  BJ10B-05 偏差 2.28e-4，面数 180→106、110→70，双双被拦回哑实体。

  这一类要与"无法识别"区分开：这两件 FeatureWorks **识别成功且特征全部建成**
  （BJ10B-04 共 50 项，含 16 旋转、6 孔向导、5 圆角；BJ10B-05 共 24 项），
  丢弃它们的是本项目的几何守卫，不是 FeatureWorks 的能力上限。
  若后续判定该体积差属拓扑清理而非几何丢失，按 SW 自整备实测值重新标定阈值即可收回这部分特征树；
  判定之前不得放宽——放宽几何守卫的后果会传导到制造端。

## DEC-034 SolidWorks 特征整备必须先严格转 XT，再特征识别

- 状态：已接受
- 日期：2026-08-17
- 取代：DEC-033 把 Parasolid 压平内联进 `SolidWorksPartPreparer`、以及 DEC-031 第 3 条「源目录里名为 XT 的文件不得当成输出目录冲突」。
- 决策：
  1. SolidWorks 特征整备与 Solid Edge 同构，分成两步：先 `SolidWorksXtExporter` 把源零件副本严格导出为交付用 `.x_t`（进度阶段 `SolidWorksExport`，界面「导出 XT」），再 `SolidWorksImporter` 对已落地的 XT 做 `LoadFile4`；勾选识别时才跑 FeatureWorks。

- 后果：版本 `4.3.16`。旧平铺产物回退仍只对 Solid Edge 开放。本条被 DEC-035 收紧：不再按原零件特征树分叉，也不再把几何改坏退回源副本。

  2. 已有 `SW/` 产物一律重做，不得复用上一轮 SLDPRT（那可能是源特征树拷贝）。有效 XT 仍可跳过导出、直接进入第二步导入识别。
  3. 识别失败、未激活、语义不合规或几何被改坏时，重新载入 XT 导入体。任何路径都不得把源零件原来的特征树拷回产物。
- 原因：用户多次要求无论原零件是否有特征都先转 XT 洗掉；残留的复用与回退源副本检测让产物仍像没洗过。
- 后果：版本 `4.3.17`。本条被 DEC-036 加上离线/真机门禁：生产代码不得再写出跳过整备文案，真机必须留下交付用 XT。

## DEC-036 特征整备门禁：禁止跳过整备，必须留下交付用 XT

- 状态：已接受
- 日期：2026-08-17
- 补充：DEC-035
- 决策：
  1. 生产 `*.cs` 不得出现「源零件已有特征树」或「跳过整备」。VERIFY-SMOKE 扫描源码；出现即失败。
  2. SolidWorks 复用计划对每个零件只能是导出 XT 或从已有 XT 导入，`ReusableSolidWorksParts` 必须为 0；`XtPath` 必须是 `XT/` 下的 `.x_t`。
  3. `SolidWorksSelfPipelineGate` 在打开产物之前核验：Worker 事件不得含上述文案；每个任务都有非空 Parasolid 文本 `.x_t`；产物不得与源零件字节相同。
- 原因：4.3.17 已删掉跳过路径，但现场仍出现「跳过整备: 源零件已有特征树」且 `XT/` 未生成。先把门禁锁死，部署槽与模块注册另走新管线。
- 后果：版本 `4.3.18`。不改旧部署脚本。

## DEC-037 SolidWorks 导出 XT 必须另存副本为 Parasolid 文本

- 状态：已接受
- 日期：2026-08-18
- 补充：DEC-036
- 决策：
  1. 从已打开的零件另存 `.x_t` 必须使用 Silent|Copy，并把 Parasolid 输出版本钉成 latest。不得把活动文档改成 Parasolid，也不得沿用会话里的二进制导出偏好。
  2. 已有 XT 若不是 Parasolid 文本，复用计划把它列入重新导出，不得整批抛 `OutputFormatInvalid`。
  3. 文本判定接受 `FORMAT=text`，以及以 `**` 开头且含 `PARASOLID` 的传输头；明确拒绝 `FORMAT=binary`。
- 原因：现场报 XT 格式导出失败。打开零件后无 Copy 的 SaveAs 会按会话偏好写出非文本，坏掉的 XT 又把整批转换卡死。
- 后果：版本 `4.3.19`。
