# SE2SW 有效决策

## DEC-001 CAD 自动化使用独立 x64 STA Worker

- 状态：已接受
- 日期：2026-08-05
- 决策：OHS UI 不持有 CAD COM 对象，Solid Edge、SolidWorks 和 FeatureWorks 调用全部在独立 Worker 中执行。
- 原因：隔离线程模型、崩溃、超时和 CAD 生命周期。

## DEC-002 运行时发现厂商组件

- 状态：已接受
- 日期：2026-08-05
- 决策：通过 COM 注册、安装目录和有效物理模板探测环境，不提交厂商 Interop DLL，不硬编码机器路径。
- 原因：兼容安装差异并保持发布包权责清晰。

## DEC-003 几何正确性优先

- 状态：已接受
- 日期：2026-08-05
- 决策：FeatureWorks 或配合重建不能通过守卫时，回退到几何完整、位置正确的结果并报告降级。
- 原因：错误特征树或漂移装配比可见降级更危险。

## DEC-004 保持隐藏 MCP 暴露

- 状态：已接受
- 日期：2026-08-05
- 决策：`mcpExposure=readonly`，真实 CAD 转换只从本机 UI 触发。
- 原因：转换依赖用户文件选择、CAD 会话和可见确认。

## DEC-005 版本只有一个人工真值

- 状态：已接受
- 日期：2026-08-05
- 决策：只编辑 `build/SE2SW.Version.props`，程序集和模块清单版本从该文件派生。
- 原因：避免 UI、Worker、Contracts 与 OHS 清单漂移。

## DEC-006 独立于 Studio工具箱维护

- 状态：已接受
- 日期：2026-08-05
- 决策：源码、项目合同和 OHS 清单唯一来源迁为 `2026-024-HistoryMinerva`（原 `2026-024-SE2SW`），
  继承自 `0000-001-AIReady`。
- 原因：SE2SW 已形成独立目标、发布线、验证体系和长期维护边界。
- 后果：`2026-019-Studio工具箱` 不再保留 SE2SW 源码或清单，历史记录保留原来源事实。

## DEC-007 生产代码与验证代码分根维护

- 状态：已接受
- 日期：2026-08-05
- 决策：生产模块保留在 `b-Code-SE2SW`；Smoke、UI Smoke、COM 探针和真实 CAD 门禁统一放在 `b-Code-SE2SW-Tests`。
- 原因：测试工程已形成独立依赖、运行环境和生命周期，不应继续混入发布模块目录。
- 后果：测试工程通过显式 ProjectReference 消费生产源码，AppShell 模块清单只引用生产构建输出。

## DEC-008 直接消费 AppShell 正式宿主快照

- 状态：已接受
- 日期：2026-08-08
- 决策：Mapping 生产工程直接引用 AppShell 3.1.9 正式快照中的 `AppShell.Core.dll`，设置
  `Private=false`；发布时固定宿主 manifest 与 Core SHA，并同时部署前端/服务端槽。
- 原因：模块公共接口、运行时上下文、命令总线和主题必须与实际宿主保持同一份精确合同。
- 后果：正式包不私带 AppShell DLL；快照版本或 SHA 变化时，发布脚本拒绝复用旧构建，必须重新验证。

## DEC-009 并入 SWuse 并改名 HistoryMinerva

- 状态：已接受
- 日期：2026-08-08
- 决策：SWuse 0.1.1（源码 `b-Code-SWuse`、清单 `z-SWuse`）自 `2026-019-Studio工具箱` 整体并入本项目，
  项目目录改名 `2026-024-HistoryMinerva`；两个模块保持各自对外名称（`Mapping`/`mapping`、
  `SWuse`/`swuse`）、版本源、程序集与发布链不变。SWuse 继续经 NuGet 引用 `OneHistory.AppShell.Core`
  3.0.3，`b-Code-SWuse/nuget.config` 显式声明 023 本地 feed；对齐 3.1.9 列为后续独立版本。
- 原因：两模块同构（Contracts + x64 STA Worker + AppShell 模块清单），同仓维护降低治理成本；
  保持既有身份与宿主合同避免功能回归。
- 后果：`2026-019-Studio工具箱` 不再保留 SWuse 源码或清单；合并细节见
  `b-Office/history/42-V4.1.0-HistoryMinerva模块合并计划.md`。

## DEC-010 4.2.0 前后端分离：双模块合并为单模块 HistoryMinerva

- 状态：已接受
- 日期：2026-08-08
- 决策：Mapping 与 SWuse 合并为单一模块 `HistoryMinerva`（指令域统一 `historyminerva`，
  无兼容别名）。前端只保留原 Mapping 中央停靠页；SWuse 独立窗口删除（界面打磨方向未定），
  其 C# 建模能力保留在协议层。所有操作代码并入单一 `HistoryMinerva.Worker.exe`，
  入口按参数形态路由 SE2SW（4 参数）/ SWuse（2 参数）两条既有协议。发布合并为
  `z-HistoryMinerva` 单清单与 `z-Package-HistoryMinerva` 单包；测试全部并入
  `b-Code-HistoryMinerva-Tests`（Smoke 合一、探针与 CadGate 归拢 tools/）。
  内部程序集与命名空间沿用 `SE2SW.*`/`SWuse.*` 不改（DEC 先例：对外改名、内部不动）。
  SWuse 一并完成 DEC-009 遗留的 AppShell 3.1.9 对齐（改用钉定快照，弃用 NuGet 3.0.3）。
- 原因：双模块同构且共享 Worker 骨架，单模块单发布单元降低部署与治理成本；
  SWuse 窗口价值未定，先退到协议层，避免为未打磨的 UI 维护宿主集成面。
- 后果：旧 `Mapping`/`SWuse`/OneHistoryStudio `SE2SW`/`SWuse` 模块槽在部署时一并退役；
  `mapping.*`、`swuse.*` 指令域作废；数据目录随模块改名迁移（`AppShell/HistoryMinerva`、
  `HistoryMinerva/HistoryMinerva`）；SWuse 0.1.x 版本线终止。细节见
  `b-Office/current/V4.2.0-前后端分离重构计划.md`。
