# V4.3.0 SolidWorks 自整备转换管线

日期：2026-08-11
状态：已实施，已通过真机验收（样件见 §5）

## 1. 需求

现场有一批**已经是 SolidWorks、但没有特征树**的装配体——多半是早年从别的 CAD 导进来的哑实体，
打开只有一个"输入1"。用户要的是：把这种 `.SLDASM` 里的零件取出来，跑本项目**已有的**特征识别与
草图完全定义管线，再装回去，装配关系照原样重建，最后仍旧交回一个 `.SLDASM`。

一句话：**源和产物都是 SolidWorks，做的是"补上特征树"，不是格式转换。**

| 编号 | 需求 | 验收方式 |
| --- | --- | --- |
| REQ-401 | 读 `.SLDASM` 得到与 Solid Edge 探查同形的读数（层级、局部/世界矩阵、配合） | VERIFY-SW-SELF §5.1 |
| REQ-402 | 每个唯一零件在**副本**上跑既有识别与草图完全定义，源文件只读 | VERIFY-SW-SELF §5.2 |
| REQ-403 | 识别不可用时产物退回源零件副本，且与源逐字节相同 | VERIFY-SW-SELF §5.2 |
| REQ-404 | 按源层级重建 `.SLDASM`，实例位置姿态与源逐元素一致 | VERIFY-SW-SELF §5.3 |
| REQ-405 | 源装配的固定组件与配合翻译为既有关系合同，参与既有配合重建 | VERIFY-SW-SELF §5.4 |
| REQ-406 | 旧协议 JSON（无 `sourceFormat` 字段）仍按 Solid Edge 执行 | Smoke |

## 2. 设计要点

### 2.1 只加一个源格式字段，不新开一条管线

`ConversionSourceFormat { SolidEdge = 0, SolidWorks }` 追加到
`BatchRequest` / `PartImportRequest` / `AssemblyProbeRequest` / `AssemblyBatchRequest` 的**末尾**，
缺省 `SolidEdge`。于是：

- 旧请求 JSON 没有这个字段，反序列化后仍是 Solid Edge，V3.x 的语义一字不变；
- 分叉只发生在最前面两步（读装配、取零件），**拓扑排序、嵌套装配生成、组件变换校验、
  配合重建、复用判定全部原样复用**，一行没改。

真正新增的实现只有两个文件：`SolidWorksAssemblyExplorer`（读 `.SLDASM`）与
`SolidWorksPartPreparer`（整备零件）。

### 2.2 没有 Parasolid 往返

Solid Edge 管线必须 `SaveBody` → `.x_t` → `LoadFile4`。SolidWorks 源不需要：零件就是 `.SLDPRT`，
复制到输出目录就能直接识别。由此得到两个白拿的好处：

1. **几何天然逐位保真**——没有中转格式，就没有中转误差；
2. **降级产物是完美的哑实体**——识别失败时把源文件再复制一遍即可，产物与源逐字节相同。
   V2.0 那套"丢弃文档、从 XT 重新导入"的补救在这里根本用不上。

`ConversionPathLayout.UsesParasolidHandoff(format)` 是唯一的判据；SW 源不创建 `XT/` 目录，
校验器也不检查 `XtPath`。

### 2.3 工作副本用唯一临时名打开

源零件与产物同名不同目录是这条管线的常态。若直接以最终名打开副本，会话里只要还开着同名的源零件，
`OpenDoc6` 就报 `swFileWithSameTitleAlreadyOpen(65536)`。因此工作副本一律用
`TemporaryOutput.For()` 的唯一临时名（`.<名>.<guid>.tmp.SLDPRT`）打开，落盘后再改名——
与导入管线同一条既有规矩。

### 2.4 产物绝不能落回源文件

输出目录若指回源目录，产物就是源零件本身，一次转换直接毁掉用户的原件。
计划器（`AssemblyPlanner`）与校验器（`WorkerRequestValidator`）**各拦一次**，
Worker 不依赖界面已经拦过。

## 3. 实测：SolidWorks 装配体 COM 面

工具 `b-Code-HistoryMinerva-Tests/tools/SolidWorksAssemblyProbe`，2026-08-11 对 Module 样件实测。
以下四条是契约设计的全部依据，不是推断：

1. `IAssemblyDoc.GetComponents(true)` 的 `Transform2` 是**本文档坐标系**下的局部矩阵；
   `GetComponents(false)` 的一律相对当前顶层文档，即世界矩阵。两者独立读出，
   正好喂给既有的 `AssemblyTransformVerifier` 互相印证。
2. 后代组件的 `Name2` 天然是 `"父-1/子-1"`，与既有 OccurrenceId 拼法逐字相同——不需要自己拼。
   实测：`消解模块-3-1/消解加热板-1` 的世界平移 = 子装配平移 + 该件在子装配内的局部平移，逐位吻合。
3. 配合挂在特征树顶层的 `MateGroup` 下，逐个子特征 `GetSpecificFeature2()` 即 `IMate2`。
4. **`IMate2` 没有 `Distance` / `Angle` 属性**。成员表里只有类型、对齐、翻转、变化范围；
   距离/角度的数值挂在 `DisplayDimension2[0].GetDimension2(0).SystemValue` 上（国际单位）。

配合几何一律用**被引用面的曲面参数乘组件变换**得到，与 `MateCandidateCollector` 在目标装配里
收集候选时走同一套换算——两边同源，匹配才有意义。不用 `IMateEntity2.EntityParams`：
它的布局随引用类型变化且未实测，猜错不报错，只静默错配。

## 4. 顺带修掉的缺陷

`SolidWorksMateRebuilder` 判"接地"时对着 `MateTypeMapperNames.Ground` 这一个字面量比较。
V4.3 起接地有两族来源（SE 的 `GroundRelation3d`、SW 的固定组件），写死其中一个，
另一族就整批落进"该层没有接地关系"的兜底分支——真机上就是这么错过 29 条固定关系的
（产物位置仍然正确，因为兜底会把未约束组件重新固定，但账目是错的）。
改为向 `MateTypeMapper` 询问 `MatePlanKind.Fix`，两族共用一条判定。

## 5. 真机验收

环境：SolidWorks 2025 SP5（RevisionNumber 33.5.0）+ FeatureWorks，
样件 `b-Code-HistoryMinerva-Tests/Module/`，
驱动 `b-Code-HistoryMinerva-Tests/tools/SolidWorksSelfPipelineGate`（走生产的探查/计划/构建三步）。

### 5.1 读装配（REQ-401）

`12位消解器-3.SLDASM`：29 个实例、13 个唯一零件、2 个装配文档、2 层。
`消解模块-3.SLDASM`：4 个实例、4 个唯一零件、1 层。
两个样件**都没有配合**，全部组件为固定件——与它们"从别处导入的哑实体"的身世一致。

### 5.2 零件整备（REQ-402 / REQ-403）

13 个唯一零件全部产出，无失败。其中：

| 结果 | 数量 | 说明 |
| --- | --- | --- |
| 生成特征树 | 2 | `cross recessed cheese head screws…`（3 个实体特征 / 3 张草图）、`XJ10B-11突跳开关压板`（3 个实体特征 / 2 张草图，完全定义 1/2） |
| 退回源零件副本 | 11 | 10 件 `CreateFeatures 返回 false`；1 件（`COD 二次样品新试剂瓶`）识别连续 10 次返回 0 |

11 件退回产物经 SHA256 核验与源零件**逐字节相同**。源目录 15 个文件的大小与时间戳在整轮转换后
一字未改，源装配 SHA256 前后一致。

`CreateFeatures 返回 false` 是既有识别阶段的**既定保守策略**（不传 `fwAllowFailFeatureCreation`，
宁可整体降级也不生成带重建错误的特征，见 DEC-003 与 05-V2.0 文档），不是本管线引入的行为；
SW 源与 SE 源在这一步走的是同一份 `FeatureRecognizer` 代码。识别命中率要不要提高，
是识别阶段自己的下一个议题，不在本版范围。

### 5.3 装配重建（REQ-404）

产物 `12位消解器-3.SLDASM` 打开 errors=0 / warnings=0，29 个组件全部与源实例配对成功，

**最大平移偏差 0、最大旋转偏差 0**（判据 1e-6 m / 1e-9）。嵌套 2 层、插入 29/29、固定 29。
整轮耗时 89.4 秒（含识别）。

### 5.4 配合重建（REQ-405）

开 `--rebuild-mates` 复跑：29 条固定组件关系全部落为"固定该组件"，
两层各自 `0/4`、`0/25` 条配合（源本来就没有配合），**0 个组件落进兜底固定**，最大漂移 0 m，
产物位置与 §5.3 一致。

**未验证项**：样件里没有真正的 `IMate2` 配合，因此"SW 配合 → 几何匹配 → 重建"这条链路
本次没有真机证据，只有离线契约测试。拿到带配合的 SW 装配体前，
建议 SW 源保持 `RebuildMates` 默认关闭（全部组件固定，位置精度与源一致）。

## 6. 未决与后续

- `MateTypeMapper` 目前只翻译 SW 的重合 / 同心 / 距离三种，其余照实带类型号进报告，不猜。
