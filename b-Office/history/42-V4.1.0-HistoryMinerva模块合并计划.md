# HistoryMinerva 4.1.0 模块合并计划

## 版本目标

将 `2026-019-Studio工具箱` 中的 SWuse 模块（0.1.1）整体并入 `2026-024-SE2SW`，合并后的项目
改名为 **HistoryMinerva**（目录 `2026-024-HistoryMinerva`）。项目内两个模块继续以既有身份
注册到宿主 `2026-023-AppShell`：

- **Mapping 4.1.0**：Solid Edge → SolidWorks 文件映射，指令域 `mapping`，中央停靠页。
- **SWuse 0.1.1**：SolidWorks C# 静态零件构建实验环境，指令域 `swuse`，自持顶层窗口。

本次合并不改变任何模块的对外名称、指令域、窗口 ID、程序集名、命名空间、Worker 进程模型、
JSON 协议和数据目录，功能行为保持不变。

## 路径与改名影响分析（不破坏功能的依据）

1. **清单相对路径不变**：`z-SWuse\module.manifest.json` 的 artifact/deps 均为
   `b-Code-SWuse/src/...` 项目根相对路径；迁入 024 根后相对布局一致，零修改继续有效。
2. **eng 脚本自定位不变**：`Update-SWuseManifest.ps1` 与 `Publish-SWuse.ps1` 由 `$PSScriptRoot`
   向上两级推导项目根再拼 `z-SWuse\module.manifest.json`；迁入后推导结果自动指向新位置。
3. **AppShell.Core 直引深度不变**：`SE2SW.csproj` 以 `..\..\..\2026-023-AppShell\...` 相对引用，
   024 目录改名不改变层级深度。
4. **项目 id 不变**：目录保留 `2026-024` 前缀，`project.manifest.json` 的 `project.id` 不改；
   `appShellHost.packageRoot` 为 `../2026-023-AppShell/...`，与目录名无关。
5. **宿主按目录扫描发现模块**：AppShell ModuleHost 只扫部署槽（`%AppData%\...\Modules\<槽>`），
   源码仓位置与模块装载无关；合并后由 OHS `tool.scan` 重新扫描即可发现新位置的清单。

## 风险与对策

- **R1 Git worktree 链接**：每个项目目录都是中央裸仓 `OneHistory-Projects.git` 的 worktree
  （`.git` 为 gitdir 指针）。目录改名必须执行
  `git --git-dir=..\OneHistory-Projects.git worktree move 2026-024-SE2SW 2026-024-HistoryMinerva`，
  禁止直接资源管理器改名。分支名 `2026-024-SE2SW` 可保留；如需同步改名另列决策。
- **R2 NuGet 源被清空**：024 根 `nuget.config` 为 `<clear/>` + 仅 nuget.org；SWuse 依赖的
  `OneHistory.AppShell.Core 3.0.3` 来自 023 本地 feed，迁入后还原会失败。对策：迁入时在
  `b-Code-SWuse\nuget.config` 新增（与 019 兄弟模块同式，相对深度相同）：

  ```xml
  <configuration>
    <packageSources>
      <clear />
      <add key="AppShell 023" value="..\..\2026-023-AppShell\z-Package-AppShell\feed" />
      <add key="nuget.org" value="https://api.nuget.org/v3/index.json" />
    </packageSources>
  </configuration>
  ```

- **R3 AppShell.Core 版本差**：SWuse 用 3.0.3、Mapping 用 3.1.9。ModuleHost 按槽独立 ALC
  装载，二者可共存；本次保持 3.0.3 不动。对齐 3.1.9（含 `IModuleContextAware` 接入）列为
  后续独立版本，不在本次合并范围。
- **R4 SWuse 数据目录常量**：`SWuseIdentity.ApplicationDataDirectoryName = "OneHistoryStudio"`
  保持不变，既有工作区数据不受影响；部署槽迁移不改变该常量。
- **R5 019 侧残留**：`2026-019-Studio工具箱\README.md` 模块表、构建命令、`tool.sync` 段落
  登记了 SWuse；迁出验证通过后删除 `b-Code-SWuse`、`z-SWuse` 并更新 README，注明去向
  `2026-024-HistoryMinerva`。

## 执行步骤（分阶段，门禁通过才进入下一阶段）

### 阶段 0 前置

- 关闭 AppShell / OneHistoryStudio 宿主与一切 dotnet 构建进程。
- 确认 019、024 两个 worktree 工作区干净（已提交）。

### 阶段 1 迁入 SWuse

1. 复制 `2026-019-Studio工具箱\b-Code-SWuse` → `2026-024-SE2SW\b-Code-SWuse`（先清 bin/obj）。
2. 复制 `2026-019-Studio工具箱\z-SWuse` → `2026-024-SE2SW\z-SWuse`。
3. 新增 `b-Code-SWuse\nuget.config`（R2）。
4. 更新 `project.manifest.json`：`activeRoots` 加 `b-Code-SWuse`、`z-SWuse`；`sourceRoots`
   加 `b-Code-SWuse`；`generatedRoots` 与 `contextExclusions` 加 `b-Code-SWuse/**/bin|obj`；
   `commands` 增补 SWuse 的 restore/build/test。

### 阶段 2 验证（改名前）

1. `dotnet build b-Code-SE2SW\src\SE2SW\SE2SW.csproj -c Release` 通过（Mapping 侧回归）。
2. `dotnet build b-Code-SWuse\src\SWuse\SWuse.csproj -c Release` 通过（R2 生效）。
3. `SE2SW.Smoke` 与 `SWuse.Smoke` 全部 PASS（含 SWuse.Smoke 对 `swuse` 指令域、
   窗口 ID、版本 0.1.1 的硬断言）。
4. `Update-SWuseManifest.ps1`、`Update-SE2SWManifest.ps1` 在新位置运行成功。
5. `b-Code\Test-ProjectContract.ps1 -Instantiation` 通过（b-/z- 前缀与 manifest 一致）。

### 阶段 3 019 侧收口

1. 删除 `2026-019-Studio工具箱\b-Code-SWuse`、`z-SWuse`。
2. 更新 019 `README.md`：移除 SWuse 行，记录迁往 `2026-024-HistoryMinerva`。
3. 在 019 分支提交（信息：`refactor: 将 SWuse 迁入 HistoryMinerva`）。

### 阶段 4 改名 HistoryMinerva

1. `git worktree move` 改目录名（R1）。
2. `project.manifest.json`：`project.name` → `HistoryMinerva`，`title` →
   `HistoryMinerva CAD 模块集`；README/AGENTS/`b-Office\current\有效决策.md` 中
   `2026-024-SE2SW` 字样同步更新。
3. 复跑阶段 2 全部验证。

### 阶段 5 宿主注册验证

1. Mapping：沿用 `Build-MappingPackage.ps1` + `Deploy-Mapping.ps1`，双槽
   `%AppData%\AppShell\Modules\Mapping` + `service\Modules\Mapping` 已在位，重建包核对
   SHA256SUMS 即可。
2. SWuse：`Publish-SWuse.ps1` 构建核验 10 个产物；部署到 023 宿主槽
   `%AppData%\AppShell\Modules\SWuse` 与 `service\Modules\SWuse`（窗口能力在 service 槽）。
   原 `%AppData%\OneHistoryStudio\Modules\SWuse` 保留至新槽验证通过后退役。
3. 宿主内 `module.list` 同时显示 `mapping` 与 `swuse`；`mapping.status`、`swuse.status`
   只读命令应答正常。
4. OHS 侧执行 `tool.scan` 刷新模块来源登记。

## 不变量清单（本次合并不得改变）

- 模块名/指令域：`Mapping`/`mapping`、`SWuse`/`swuse`；窗口 ID `mapping`、`swuse`。
- 程序集与命名空间：`SE2SW*`、`SWuse*` 全部不改名。
- 版本源：`SE2SW.Version.props`（4.1.0）、`SWuse.Version.props`（0.1.1）各自独立。
- Worker 均为独立 x64 STA exe，随 deps 部署；`SWuse.Worker` 继续携带 Roslyn 两个程序集。
- `mcpExposure`：Mapping `readonly`、SWuse `hidden`。
- SWuse 自持顶层窗口、桌面 Shell 弃权停靠的行为不变（V0.1.1 起不自动开窗）。
- 数据目录：Mapping 用 `IModuleContext.DataDirectory\Mapping`；SWuse 用
  `%AppData%\OneHistoryStudio\SWuse`。

## 验证边界

Release 构建、双 Smoke、清单同步、AIReady 合同、`module.list` 注册核验属于本次合并门禁。
不改任何 Worker 协议与 CAD COM 实现，不重复运行真实 CAD 门禁（SWuse.CadGate、Mapping 各
探针），沿用既有真机验收证据。Mapping 的 UI Smoke 仅在后续界面变更时重跑。

## 回退

任一阶段门禁失败：阶段 1–2 删除新拷贝的 `b-Code-SWuse`、`z-SWuse` 即恢复原状；阶段 3 之前
019 侧保持完整，天然可回退；阶段 4 改名可用 `git worktree move` 反向执行；阶段 5 部署槽
删除新槽目录并恢复原槽即可。
